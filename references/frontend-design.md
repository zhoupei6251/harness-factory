# 前端页面设计参考

> 仅在新建页面、调整视觉或检查 UI 时按需读取。三个上游已于 2026-10-30 核对；本仓库只记录参考，不自动安装插件、执行上游脚本或引入依赖。

## 按任务选择一个主参考

| 当前任务 | 主参考 | 重点借鉴 |
|---|---|---|
| 已有页面不够精致、排版混乱，需要改进或审查 | [pbakaus/impeccable](https://github.com/pbakaus/impeccable) | 用 critique / audit 确定问题优先级，再按 typeset、layout、polish 等单项指引改善；检查可访问性、响应式和性能。 |
| 从零设计页面，需要鲜明风格和真实产品感 | [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill) | 从产品独有信息确定视觉方向，组织图片、版式和内容，在真实浏览器检查页面；应用页面重视数据层级与清晰布局。 |
| 后台、表单、仪表盘，需要设计系统或具体 UX 规则 | [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | 按产品、页面和现有技术栈查配色、字体、图表与交互建议，重点检查长文本、窄屏、标签和控件状态。 |

先读所选仓库 README，再取当前问题需要的章节。只有遇到具体缺口才补第二个参考；不要每次预加载三个仓库或串行运行它们的完整流程。上游命令名表示设计意图，只有实际安装并可用时才执行对应命令。

## 实施顺序

1. 先看当前路由、相邻页面、组件库和样式变量，复用已有组件、字体、间距与交互约定。
2. 明确页面用户、核心动作和视觉方向；已有设计稿或品牌规范优先。信息足够就直接实现，不为风格选择反复暂停。
3. 按一个主参考完成页面。先建立内容层级、布局与可用交互，再处理颜色、字体、图片和必要动效；避免机械套用渐变、卡片和装饰。
4. 验证正常、加载、空数据、错误与禁用状态；表单应有标签和错误反馈，控件支持键盘与可见焦点，颜色不能独自表达状态，动效尊重减少动画偏好。
5. 有浏览器工具时，检查桌面与移动宽度，操作关键流程并查看截图；修复溢出、遮挡、断行和点击问题。没有工具时明确未做视觉验证，并保留实际可执行的验证步骤。

默认复用项目依赖。为了参考一种视觉风格，不额外安装组件库、字体包、动画库或运行长时间多轮生成；确有需求时再按项目流程选择。使用外部图片时保留来源与授权信息。
