# 常见代码陷阱

按当前改动选择相关项，不在每个任务开始时全量加载。

| 陷阱 | 避免方式 |
|---|---|
| 未读源码就修改 | 先定位符号、调用者和真实输入，再做最小修改 |
| 事务提交前更新缓存或释放锁 | 明确提交与并发边界，验证回滚路径 |
| AOP 自调用绕过代理 | 检查事务/异步方法的实际调用路径 |
| 异步任务丢失租户、用户或 TraceId | 显式传递上下文并检查隔离 |
| 改 id 就能操作他人数据 | 在服务端校验权限、租户和资源归属 |
| SQL 拼接与 N+1 查询 | 参数化查询；批量读取关联数据 |
| 相信客户端价格或金额 | 服务端计算并验证金额与状态 |
| 空 catch 或静默默认值 | 处理预期错误，未知错误携带上下文上抛 |
| 敏感信息写进源码或日志 | 使用项目已有配置渠道并脱敏日志 |
| 单次使用就增加工厂、策略和依赖 | 先复用、用标准能力，确有重复再抽象 |
| 只检查成功路径 | 对新分支、异常和关键边界补有意义的验证 |
| 反复运行相同全量检查 | 一批修改后验证；只有新修改、失败或新增疑点才重跑 |

前端视觉与交互检查见 [frontend-design.md](frontend-design.md)。
