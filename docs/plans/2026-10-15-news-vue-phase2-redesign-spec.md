## 0. 为什么要改判

Phase 1 的 Global Constraints 有一条用户 2026-10-14 拍的「**1:1 保真：本 Phase 不改变任何包的视觉**」，
Phase 2 原样继承它，判据是 `routes/news/scripts/vue_pixel_ab.py`（静态支 vs Vue 支同 seek 比 PSNR）。

redesign 与这条判据**逻辑互斥**：`vue_pixel_ab` 测的就是"和旧版一样"，改版式必然判红。
不先换判据就开工，结果会是同一份代码同时"通过"和"不通过"。⇒ 本 spec 的第一件事是换判据（§2）。

## 1. 范围：先把工作量说准

`t_slots_reconstruct_every_pack_byte_exact`（Phase 1 Task 1）机检证明：
**同一角色的 31 份静态文件，跨包差异只有「有序 hex 列表 + composition_id」，其余逐字节相同。**

⇒ 今天系统里真实存在的设计不是 217 个，而是 **7 个版式 ×（主流簇 + news-policy 变体簇）= 14 个组件**，
外加 31 套配色（配色成立性已由 `audit_pack_contrast.py` 复算，24 条 OFF_PALETTE_HEX 是刻意保留基线）。

- **在范围内**：14 个 Vue 组件的设计质量；图板下沉到组件；3 条契约增补；判据替换；
  **4 个新结构**（§7 —— 用户 2026-10-15 追加裁决「不同题材用合适的结构」）。
- ~~不在范围内：给不同题材做不同结构~~ —— **已纳入 §7**。"那是另一个量级"的判断仍然成立，只是用户选了做。
- **不碰**：`hf_compile.py` / `path_c` / `spec.toml`（迁移总纲 §1-4 仍然有效）。

### 1.1 两条已被实测否证的配色路线（记下来，别再试）

用户选了「story 随包变色」，两条实现都跑了全 31 包：

| 路线 | 实测 |
|---|---|
| 绑面色（各包 `paper`/`ground` token） | 10 包变色，但最大 Δ **12/255**；**只有 `news-world` 肉眼可辨**；21 包被对比度闸退回 |
| 绑 accent（各包 identity 色） | 8 个非红族包里 **6 个过不了 3.0**：`bulletin`/`onsite` 黄 light 面 **1.30**、`world` 藏青 dark 面 **1.30**、`policy` 钴蓝 dark 面 **1.75**、`ink` 金 light 面 **1.96**、`explainer` dark 面 2.95 |

根因：story 的两个面是**中性纸/墨**，各包的中性 token 本就是同一组近白近黑；包身份色天然与其中
一个面冲突。共享珊瑚（`SHARED_TOKENS` 的 `shared-accent*`）不是保守，是**算出来只有它在两个面都站得住**。
⇒ 包间差异走**结构**（§7），不走配色。相关代码 `theme_slots` 未接线即删。

## 3. 设计契约增补三条（全部来自 2026-10-15 实测帧）

### A. 装饰层不许吃通用文字阴影 —— 这是实现违反自己的契约

`frame.md` §2 字阶明写壁纸序号 = **`22–52cqw`，12% ink + `data-layout-ignore`**。
而 v007 为兜 WCAG AA 加的通用规则把它打回实黑：

```css
#root > *:not([class$="-photo"]):not([class$="-photo-credit"]) {
  text-shadow: 0 1px 3px rgba(0,0,0,.7), 0 0 1px rgba(0,0,0,.5);
}
```

实测：story 的「02」CSS 写 `rgba(26,26,26,0.12)`，渲染帧该区域**最暗像素 (27,25,24)**（≈实黑），
两层阴影叠加所致。命中面量过：含该通用规则的 composition **212 份** + `hook-a` 组件 1 份，
其中真正带装饰件（`data-layout-ignore`）的文件 **126 份**。

- **修法**：该选择器加 `:not([data-layout-ignore])`，212 + 1 全改（不只改那 126 份 ——
  规则本身是"给所有 root 子元素兜底"，留着不改，将来新加的装饰件会再次中招）。
  文字元素（真正需要阴影兜 AA 的）一个不动。
- **机检两条，一条静态一条真判**：
  - 静态 `t_decorative_layers_excluded_from_text_shadow`：任何含 `data-layout-ignore` 的文件，
    其通用 `text-shadow` 选择器必须出现 `:not([data-layout-ignore])`；缺即点名文件。反向负例：
    临时去掉一个文件的该 `:not()`，断言必须变红。
  - 像素 `t_watermark_renders_at_declared_alpha`（真判据）：固定 fixture 渲 story 一镜，
    `hyperframes snapshot` 取帧，量序号区域最暗像素。声明 `rgba(26,26,26,.12)` 叠在
    cream(233) 上应得 ≈208 ⇒ 断言**最暗 ≥ 190**（容差 18）。修前实测 27，必红 —— 这条
    比静态检查强，因为它测的是"最终合成出来的像素"，而不是"我假设 CSS 会怎么生效"。

### B. 图板归组件，且无图不许留任何许可指向

已落地一半：212 份静态版式补 `display:none` + `hasPhoto` 点亮；`hook-a` 补 `v-if="hasPhoto"`
（**我第一轮只扫了 `templates/`，漏了 Vue 支**，被用户「不是都用 vue 了吗」问出来）。
断言 `t_imageless_shots_never_show_photo_credit` 现覆盖两支，并验证过 HEAD 版 hook-a 会被判红。

Phase 2 要求：**6 个新组件每个自带图板**（用户 10-14 已拍「图板由 Vue 支承接」），
且接 P3 grade 机制 —— 非现场真图必须走 `schematic` 三轨免责标注，不许以"真实照片"身份上屏。
Commons 里不存在"宁波这套房"，通用图一律是**示意**。

### C. 屏上文字必须有断点，不许出现孤字

根因实测：`fitCqw()` 只按行数缩字号，`perLine = floor(BOX_CQW / base) = floor(88/8.6) = 10`；
11 字领句 → 2 行 ≤ 3 行上限 → **字号不动** → 浏览器贪婪折行切出「六月报平安，九月成废 / 墟」。
CJK 可任意位置断行，而 `HEAD_BREAK_CHARS`（`，、｜`）这套作者标记早就存在，只是 fit 逻辑不看它。

- **修法**：fit 与换行都按**断点分段**算——每段必须 ≤ 一行容量，放不下就缩字号或换版式，
  绝不让浏览器决定在哪断。
- **机检**（`t_no_orphan_line_break`）：对每个角色用边界稿（每段恰好 1 字、总长恰好容量+1）
  渲染 snapshot，逐行扫描墨迹，**任一行可见字符数 < 2 即判红**；同时断言断点字符不残留在屏上。
- 顺带更正我自己的误判：我曾把「story 中间大片留白」列为契约缺口。实测该版式内容**居中**、
  上下各余 12.2cqh 是文件头写明的设计。**留白不是缺陷**，真正的破坏者只有 A 和 C。

## 4. 架构

```
组件（14 个，Vue SFC，src/web/entries/<role>-<a|b>/）
  ├─ 只读 var(--cNN) 有序色位槽（发射器按包注入，Phase 1 已闭环）
  ├─ 自带图板 + grade 通道（B）
  ├─ 断点感知的 fit 逻辑（C）
  └─ 装饰层与文字层分离，阴影只归文字（A）
        ↑
  vue_bundle_for(pack, role) → f"{role}-{variant_of(pack, role)}"（Phase 1 Task 4）
        ↑
  CUTOVER_ROLES: {"hook"} → 逐角色扩到 7 个（每过一个角色的 §2 全套判据就登记一个）
```

静态支在 Phase 2 期间**继续服务未 cutover 的角色**（今天的 story/closer 就是它渲的），
A、C 两条修复**两支都要**——静态支还要活到 Phase 3，不能把丑留在将死分支里。

## 6. 风险与未决

1. **「好看」的天花板不在代码里**：14 个组件重写完，如果只用 31 套配色，题材间的视觉差异仍然有限。
   要不要给不同题材不同结构（§1 明确排除项），需要一次单独的 brainstorm。
2. **目视判据不可约**：§2 最后一行是人工的。我不提议给它编分数——那会造出一个
   "真片与假片分布重叠"的指标，按既有规矩那种指标该删不该设阈值。
3. **BGM 的授权与成本**：`media-use` 的 resolve 路径要落盘冻结文件，零云费口径是否覆盖音乐许可未证。
4. **发布仍卡两把锁**（既有）：抖音账号未登录；`--aigc-producer` 仍是默认值 `harness-news-pathb`，
   真要发得先定主体名重渲。redesign 不解决这两条。
5. **本轮未提交**：212 静态文件 + hook-a + 两条断言（全闸绿）与 P2-0 会落在同一批模板文件上，
   建议先 commit 再开 P2-0，否则 diff 混在一起没法审。
   —— 已按此执行（`bd7b5a7`）。

## 7. 结构扩展：不同题材用合适的结构（用户 2026-10-15 追加裁决）

把 `decide_pack.PACK_BUCKETS` 的 **14 类题材**逐类对着现有 7 个角色（`hook/story/stat/quote/catalog/rail/closer`）
核对信息形状：**10 类现有角色装得下**（只是配色不对），**4 类装不下** —— 那 4 个才是真缺口。

| 新结构 | 装什么信息形状 | 现有角色为什么不行 | 受益题材 |
|---|---|---|---|
| **`field` 现场镜** | 影像占 ≥60%，文字压底一行 | **7 个角色全是文字主导**，图板只是"贴一张小图" | onsite / world / thread / dawn / person_story / alert（6 类） |
| **`rank` 排行榜** | TOP-N：名次 + 名称 + 量级条 | `rail` 是无序 label/value 行，**没有名次、没有量级**；`stat` 只放 1–2 个数 | data / blast / bulletin |
| **`versus` 双栏对照** | A vs B 同构多属性两栏 | `stat` 只支持**一组** `compareValue` | policy / blast / polarity / world / investigation |
| **`cause` 因果链** | 因→果、分支、机制分解 | `catalog` 是**线性步骤**，语义不对（步骤 ≠ 因果） | explainer / alert |

顺序：**`field` 先行** —— 它是"好看"的最大单一杠杆（新闻短视频的画面主体该是影像），
且顺手逼出 §5 的 P2-1 图板基座，后三个结构复用。

### 7.1 `field` 的硬前提：图必须分三态，且默认不是"真图"

实测供给（`commons_media` 的三道授权/尺寸/词面闸，10 条真实题材查询）：命中率 **9/10**，
但**相关性闸只认 1 个拉丁整词**，语义在漂：

| 查询 | 实际放行 |
|---|---|
| `factory assembly line workers` | **An armored car near the end of the assembly…**（装甲车） |
| `earthquake damaged building` | 福井地震 **1948**（78 年前、日本） |
| `press conference podium` | 里根（1980s 美国总统） |
| `police tape crime scene` | **NYPD** 警戒带 |

文字版式里这只是角落一块图板；**`field` 里图占 ≥60%，一条错位图就是一条视觉假事实**，
比无图更糟（与 D21② 同源，只是这次是画面主体）。⇒ `field` 必须设计成三态，且**真图是例外不是默认**：

| 态 | 触发条件 | 画面口径 |
|---|---|---|
| `real` | 报道自带、且能追溯到发布主体的授权图（**当前采集链没有这条，是缺口**） | 可占 ≥60%，按图来源署名 |
| `schematic` | Commons 命中**且通过 §7.3 类别一致性** | 占 ≤62% + 常驻「示意画面 · 非事件现场」标 + 授权署名 + 降饱和；**不做 Ken Burns** |
| `none` | 三闸或类别比对任一不过 | **一等公民设计**：ghosted 事实当画面主体（见 §7.2），不是留空洞 |

原型实测（2026-10-16，`.harness-news-runtime/probe/field-proto/`，两态各渲 5s/18s 出片）：
`none` 态成立 —— `1000万` 以 12% 墨作主体 + 斜纹地面，无空洞感。两处待改：
眉标不许写「现场无影像」这类**道歉式文案**（换成事件/栏目词），
且 36–62cqh 之间有一条空带需要压掉。

### 7.1.1 角标不足以对冲画面的断言力（原型给出的结论）

原型用 `vacant apartment building` 命中的那张图（**拉脱维亚 2008 年木楼破窗**）配
「宁波高端小区、室内精装被拆成毛坯、外观完好」这条新闻 —— 左上「示意画面 · 非事件现场」
白字黑边、字号够、位置正，**但看着自己渲出来的帧，第一反应仍是"房子被砸破窗了"**。
画面在断言一件没发生的事，而角标只是文字。⇒ 光标注不算合规完成，必须有 §7.3 那道拦。

### 7.2 `none` 态的设计口径

无图不是降级残局：顶部画面区用**本镜最关键的事实**做 ghosted 主体（12% 墨，与 story 的
序号水印同一套语言，因此复用 §3-A 的"装饰层不吃通用阴影"规则），配斜纹地面 + 顶光；
底部文字带坐在字幕禁入区（20cqh）上方。**眉标只放事件词/地名，不放"无图"类自证文案。**

### 7.3 示意图的类别一致性闸（硬约束，用户 2026-10-16 裁决）

`schematic` 图必须与**本镜正文**在同一事实类别上不打架，三个维度全部可机检（纯词面，不依赖视觉模型）：

| 维度 | 规则 | 拦的就是原型那次 |
|---|---|---|
| **场景类** | 作者在分镜声明 `imageScene ∈ {interior, exterior, street, person, device, aerial}`；文件名须含该类的受控词表命中项。讲室内不得配建筑外观 | 破窗**外观**配**室内**被拆 |
| **地域** | 正文出现中国地名时，文件名含**具体境外地名/国名**即拒；无地域线索才放行 | **拉脱维亚 Leveri** 配宁波 |
| **状态** | 损毁类词（`ruin/rubble/broken/demolished/destroyed/fire`）只有正文自身断言同一状态时才允许 | 正文说外观完好、图是砸烂的 |

任一维度**比对不出来就落 `none` 态** —— 宁可无图，不许错图（与 D21② 同一立场：
「2 字地名不再放行」的代价是有时没图，收益是绝不配错图）。

⚠️ **代价已量（2026-10-16）**：把三个维度套到 §7.1 那 10 条真实题材查询上，
三闸命中率 **9/10 → 类别闸后 2/9**；而那 2 条存活是本次粗词表漏判
（`armored car` 被当成 device、`Wind turbine field - US-54 - Kansas` 没进境外地名表）。
按应有的主体比对，**真实存活率是 0/9**。

⇒ **结论不是"闸太松"，是"库存不对"**：Commons 几乎没有中国新闻事件的可用影像。
所以本 spec 的排序调整如下，`field` 的图态**不在本轮实施**：

1. `field` 先按 **`none` 单态**落地 —— 原型已成立（§7.2），只待改眉标文案与中部空带。
2. **图供给升级为新闻域的独立前置缺口**（见 §7.5），它不解决，`field` 的 `real`/`schematic` 态就是空谈。
3. §7.3 这道类别闸**保留为"将来有图时的硬约束"**，但不在本轮建 —— 给一个 0/9 的供给建闸门是本末倒置。

### 7.5 图供给缺口（新旗标，未拍）

`field` 的价值上限由这条决定，三条路各有明确代价：

| 路 | 说明 | 代价 |
|---|---|---|
| 报道正文授权图 | 采集时抓正文图并记来源/授权 | `news-collect` 现在明确「不做正文抓取」；版权与可追溯性要新判据；境外源基本不可用 |
| AI 生图 | 按分镜生成示意画面 | 与「零云费」口径冲突；且必须走 AIGC ①③ 标识，**生成画面配新闻=造事实**，风险高于示意图 |
| 接受无图 | `field` 就是 none 态 | 放弃"影像主导"这个卖点；但零风险、今天就能做完 |

**我的判断**：先接受无图（第 3 条），把 `field` 的 none 态做扎实；同时**先做 `rank` 和 `versus`** ——
