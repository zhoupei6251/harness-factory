# Structure

Canonical sources are edited directly; distribution artifacts are regenerated. This repository has one route: `code`.

## Canonical sources

| Path | Purpose |
|------|---------|
| `ENTRY.md` | Shared behavior and loading policy |
| `rules/` + `guides/` | Split by when they load: `rules/` every session, `guides/` on demand |
| `agents/<role>.md` | Role behavior contracts (canonical); target projects keep thin wrappers whose `core:` points here |
| `stacks/` | Three verticals: common, java, typescript; patterns/security/testing/hooks guidance |
| `platforms/<p>/platform.json` | Capability matrix per host: configDir, nativeEntry, renderDir, skillsDir, agentsDir, agentFrontmatter. Every script reads it — no script keeps its own copy |
| `platforms/<p>/rules/ENTRY.md` | Five adapters: claude, codex, trae, workbuddy, qoder — prose delta only |
| `templates/code-MEMORY.md` | Neutral initialization template, not live project state |
| `skills/<name>/SKILL.md` + `_meta.json` | Active software-engineering procedures |
| `skills/hf-*/upstream/`, `skills/ponytail/upstream-LICENSE` | Fixed upstream subsets and licenses; local SKILL.md adapters define scope |
| `skills/archive/` | Inactive coding skills; not installed by `skills:install` |
| `tools/schemas/` | Platform/route/skill JSON schemas |
| `references/mcp/` | External graph-tool configuration snippets |
| `references/` | Setup, lessons, and on-demand frontend design references |
| `references/upstreams.lock.json` | Source repositories, exact revisions, original paths and content hashes |
| `templates/` | Downstream target entries, overview template and shared harness template |
| `projects/<name>/CLAUDE.md` | A downstream project's finished CLAUDE.md. It lives here because the project copy is gitignored and is destroyed by branch switches that still track it; `install-into-project` prefers this copy over the generic template |

See `skills/INDEX.md` and `npm run stats` for live counts.

## Executable code and records

| Path | Purpose |
|------|---------|
| `tools/scripts/*.ts` | Bootstrap, installation, audit, index and maintenance commands |
| `tools/tests/*.test.ts` | Assertion-bearing generator and installer tests |
| `tools/scripts/bootstrap-contract.ts` | Shared bootstrap input/output ownership contract |
| `records/plans/` | Current durable plans when complexity warrants a record |
| `records/verifications/` | Necessary repository verification/review records |

There is no product frontend or media renderer in this repository. Frontend work in target projects is guided by `references/frontend-design.md`.

## Generated distribution and local state

| Path | Ownership |
|------|-----------|
| `CLAUDE.harness.md`, `AGENTS.harness.md`, `GEMINI.harness.md` | Generated from `templates/harness.template.md`; tracked for downstream use |
| `CLAUDE.md`, `AGENTS.md` | Generated native entries; gitignored |
| `.claude/`, `.codex/`, `.trae/`, `.codebuddy/`, `.qoder/` | Generated platform projections; gitignored |
| Root `MEMORY.md` | Mutable project state, initialized only if absent; gitignored |
| `.ai-runtime-artifacts/` | Code task scratch/runtime; gitignored |
| `node_modules/` | npm-managed dependencies; gitignored |

No root `GEMINI.md` is generated by bootstrap. The downstream installer still renders a target-project `GEMINI.md` using `GEMINI.harness.md`.

`npm run check-bootstrap` regenerates in a temporary copy and compares content. Edit the sources, then run `npm run bootstrap`; do not hand-edit generated entries. Existing root `MEMORY.md` is preserved and is not a generated-byte invariant.

## Where to add things

- Coding skill: `skills/<name>/SKILL.md` and `_meta.json`; regenerate the index.
- Language rule: `stacks/<language>/<topic>.md`.
- Executable maintenance command: `tools/scripts/<name>.ts`, with a package script when useful.
- Behavior test: `tools/tests/<name>.test.ts`.
- Reference: `references/<topic>.md`, linked from the relevant task entry.

Keep documents out of `tools/scripts/`, non-tests out of `tools/tests/`, and runtime dumps/dependencies out of tracked source paths. Skill directories must have both metadata and instructions. Do not place a whole application project inside a globally installed skill directory.
