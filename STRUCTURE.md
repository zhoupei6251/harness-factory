# Structure

Canonical sources are edited directly; distribution artifacts are regenerated. This repository has one route: `code`.

## Canonical sources

| Path | Purpose |
|------|---------|
| `ENTRY.md` | Shared behavior and loading policy |
| `core/` | Eight governance documents, loaded by task |
| `capabilities/rules/` | Three verticals: common, java, typescript; patterns/security/testing/hooks guidance |
| `platforms/<p>/rules/ENTRY.md` | Five adapters: claude, codex, trae, workbuddy, qoder |
| `routes/code/MEMORY.md` | Neutral initialization template, not live project state |
| `skills/<name>/SKILL.md` + `_meta.json` | Active software-engineering procedures |
| `skills/archive/` | Inactive coding skills; not installed by `skills:install` |
| `schemas/` | Platform/route/skill JSON schemas |
| `mcp-config/` | External graph-tool configuration snippets |
| `references/` | Setup, lessons, and on-demand frontend design references |
| `templates/` | Downstream target entries, overview template and shared harness template |

See `skills/INDEX.md` and `npm run stats` for live counts.

## Executable code and records

| Path | Purpose |
|------|---------|
| `scripts/*.ts` | Bootstrap, installation, audit, index and maintenance commands |
| `tests/*.test.ts` | Assertion-bearing generator and installer tests |
| `scripts/bootstrap-contract.ts` | Shared bootstrap input/output ownership contract |
| `docs/plans/` | Current durable plans when complexity warrants a record |
| `verifications/` | Necessary repository verification/review records |
| `docs/superpowers/` | Historical design records; not automatically loaded |

There is no product frontend or media renderer in this repository. Frontend work in target projects is guided by `references/frontend-design.md`.

## Generated distribution and local state

| Path | Ownership |
|------|-----------|
| `CLAUDE.harness.md`, `AGENTS.harness.md`, `GEMINI.harness.md` | Generated from `templates/harness.template.md`; tracked for downstream use |
| `CLAUDE.md`, `AGENTS.md` | Generated native entries; gitignored |
| `.claude/`, `.codex/`, `.trae/`, `.codebuddy/`, `.qoder/` | Generated platform projections; gitignored |
| Root `MEMORY.md` | Mutable project state, initialized only if absent; gitignored |
| `.ai-runtime-artifacts/` | Code task scratch/runtime; gitignored |
| `node_modules/` | npm-managed dependencies; gitignored |

No root `GEMINI.md` is generated by bootstrap. The downstream installer still renders a target-project `GEMINI.md` using `GEMINI.harness.md`.

`npm run check-bootstrap` regenerates in a temporary copy and compares content. Edit the sources, then run `npm run bootstrap`; do not hand-edit generated entries. Existing root `MEMORY.md` is preserved and is not a generated-byte invariant.

## Where to add things

- Coding skill: `skills/<name>/SKILL.md` and `_meta.json`; regenerate the index.
- Language rule: `capabilities/rules/<language>/<topic>.md`.
- Executable maintenance command: `scripts/<name>.ts`, with a package script when useful.
- Behavior test: `tests/<name>.test.ts`.
- Reference: `references/<topic>.md`, linked from the relevant task entry.

Keep documents out of `scripts/`, non-tests out of `tests/`, and runtime dumps/dependencies out of tracked source paths. Skill directories must have both metadata and instructions. Do not place a whole application project inside a globally installed skill directory.
