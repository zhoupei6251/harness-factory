# Structure

> What lives where in `harness-factory`. Read this before adding a new file — it
> exists so each directory has exactly one job, and so new files have an obvious
> home.

## Top-level

| Path | Purpose | Mutable? |
|---|---|---|
| `ENTRY.md` | Single source of truth for behavior rules (all 5 platforms). | edit cautiously |
| `CLAUDE.md` / `AGENTS.md` | Native entries Claude and Codex+Qoder auto-load; **generated by `npm run bootstrap`** (gitignored). | regenerated |
| `CLAUDE.harness.md` / `AGENTS.harness.md` / `GEMINI.harness.md` | Distributable harness rules, generated from `templates/harness.template.md`. **Tracked** — they are what a downstream project reads, so they ship in git. | regenerated, then commit |
| `LICENSE` | Project license. | frozen |
| `README.md` | Onboarding: what + quick-start. | edit |
| `ARCHITECTURE.md` | Why-the-shape: 6 layers, what was cut, bootstrap contract. | edit |
| `STRUCTURE.md` | This file: where each kind of file lives. | edit |
| `MEMORY.md` | Code-route MEMORY for the **downstream** project (gitignored, bootstrap-generated). | regenerated |
| `package.json` | npm scripts + TS deps. | edit |
| `tsconfig.json` | TS 7 config for the meta toolchain (`core` / `scripts` / `tests`). | frozen unless compiler bumps |
| `tsconfig.web.json` | TS config for the web layer only (`src/web/**` + `vite.config.ts`). Adds `DOM` lib. Checked by `npm run typecheck:web`. | edit |
| `vite.config.ts` | Vite build for `src/web/` → `dist/`. Entries are **directory-driven**: it scans `src/web/entries/*/main.ts` and generates each rollup input itself. | edit only for output/layout changes |
| `.mcp.json` | Project-scoped MCP server wiring (committed). | edit |
| `.gitignore` | What stays out of git. | edit |

## Source dirs (canonical, edit these)

```
core/                  8 governance docs (NEVER, ENTRY, principles, ...). Mandatory load.
capabilities/rules/    Per-language rules. 3 verticals: java, typescript, common.
                       4 file types each: hooks.md, patterns.md, security.md, testing.md.
platforms/<p>/rules/   Per-platform deltas. 5 platforms: claude, codex, trae, workbuddy, qoder.
                       codex + qoder share native entry AGENTS.md.
routes/<r>/            Per-domain state. 3 routes: code, novel, news.
                       MEMORY.md is the per-route template.
                       news/ has extra sub-dirs (evidence/, scripts/) because it is the
                       only route that has shipped production code.
skills/                Active skills (49) + skills/archive/ (51). Restorable on demand.
schemas/               JSON schemas: platform / route / skill / sample. Validated by scripts/validate-schemas.ts.
mcp-config/            Canonical MCP server snippets (1 server: codebase-memory).
references/            tooling.md + traps.md — external tool setup notes.
examples/              Tracked sample input data for the news route (sample/*.json +
                       MANIFEST.md + licenses/). Rollback/regen source for
                       scripts/seed_sample_fingerprint.py — real data, so it ships in git.
docs/superpowers/      Design specs (specs/) and implementation plans (plans/) — the
                       registered home, 10 files, all tracked.
                       ⚠ Duplicate home: docs/plans/ (4 files, 1 tracked) holds the same
                       kind of document and is NOT registered anywhere. Unresolved as of
                       2026-10-13 — pick one before the next plan is written.
```

## Code dirs (TS)

```
scripts/               Harness-factory's own meta scripts (run via npm run *).
                       bootstrap, bootstrap-contract, doctor, install-into-project,
                       install-skills, stats, check-bootstrap, skills-audit,
                       build-index, validate-schemas, plus the skill seed script.
                       `scripts/bootstrap-contract.ts` is the machine-checked
                       contract (inputs + generated paths) shared by
                       check-bootstrap.ts and both integration tests.

                       Invoke by npm script key where one exists (see
                       `package.json`); `install-into-project.ts` and
                       `bootstrap-contract.ts` have no key — run them with
                       `npx tsx scripts/<name>.ts`. `seed_sample_fingerprint.py`
                       is the one Python file here: a one-off news-sample URL
                       seeder (docs/plans/2026-10-12-sample-data-truesource-
                       foundation-design.md), not part of the bootstrap chain.

tests/                 Real tests only: bootstrap.test.ts (smoke, temp root),
                       install-template.test.ts, downstream-render.test.ts,
                       tests/web/vue-build.test.ts (vite build + 13 product assertions,
                       runs its own build — no separate build step needed).
                       The old tests/validate-schemas.ts and tests/build-index.ts moved to
                       scripts/ — they are scripts, not tests.
```

## Web layer (Vue + Vite — the only build-stepped source)

```
src/web/entries/<name>/   One Vue composition = main.html (Vite html entry) + main.ts
                          (exports mount(target, compositionId)) + <Name>.vue.
src/web/lib/              Shared by entries: gsap-runtime.ts, hyperframes-bridge.ts,
                          data.contract.ts. This sharing is a reason the
                          layer is NOT under skills/ — see ARCHITECTURE.md.
src/web/vue-shims.d.ts    declare module "*.vue" — needed because .vue type checking is
                          unavailable (vue-tsc × TypeScript 7, see below).
```

`.vue` files are deliberately **not** in `tsconfig.web.json` `include`: plain `tsc` cannot
parse them, and `vue-tsc@2.2.12` crashes before reading any config because `typescript@7.0.2`
no longer exports `./lib/tsc`. So `typecheck:web` covers `src/web/**/*.ts` + `vite.config.ts`
and **nothing inside `<script setup>`**. esbuild (via `vite build`) strips types and checks
none of them — it is not a substitute. The recovery path is tracked in
`verifications/2026-10-13-hyperframes-vue-poc-verification-lite.md`.

`dist/` is the second class of generated output. It is owned by `vite build`, **not** by
bootstrap: it is absent from `BOOTSTRAP_INPUTS` and `GENERATED_FILES`, so `check-bootstrap`
cannot see it and does not guard it. It stays out of git via `.gitignore` (`dist/`).

## Bootstrap outputs (regenerated, do not hand-edit)

```
.claude/  .codex/  .trae/  .codebuddy/  .qoder/     per-platform rules/ENTRY.md + rules/ROOT.md
.trae/rules/project_rules.md  .codebuddy/rules/project_rules.md
AGENTS.md  CLAUDE.md  MEMORY.md                     native entries + projected route MEMORY
AGENTS.harness.md  CLAUDE.harness.md  GEMINI.harness.md   from templates/harness.template.md
.harness-novel-runtime/  .harness-news-runtime/  .ai-runtime-artifacts/   runtime dirs
```

Everything here except the three `*.harness.md` is gitignored. There is no root
`GEMINI.md`: bootstrap has no Gemini adapter, and `GEMINI.harness.md` is read by the
`GEMINI.md` that `install-into-project` writes into a *downstream* project.

`scripts/check-bootstrap.ts` re-runs the generator against a throwaway copy of the
sources and compares bytes, so a stale or hand-edited artifact fails. `npm test` runs it.

## Domain runtime (per-route, gitignored)

| Route | Runtime dir | Owns |
|---|---|---|
| `code` | `.ai-runtime-artifacts/` | agent traces, scratch |
| `novel` | `.harness-novel-runtime/` | novel drafts, chapter output |
| `news` | `.harness-news-runtime/` | rendered videos, ledger, articles |

`scripts/stats.ts` reports their sizes (flag >1 GiB).

## Where to add a new thing

| You want to add… | Put it in… | Read |
|---|---|---|
| A new skill | `skills/<name>/SKILL.md` + `_meta.json` | `skills/add-skill/SKILL.md` |
| A new platform | `platforms/<name>/rules/ENTRY.md` | `skills/add-platform/SKILL.md` |
| A new route | `routes/<name>/MEMORY.md` | `skills/add-route/SKILL.md` |
| A new language rule | `capabilities/rules/<lang>/<topic>.md` | this file |
| A new npm script | `scripts/<name>.ts` + `package.json` entry | existing scripts for style |
| A new test | `tests/<name>.test.ts` (web-layer: `tests/web/<name>.test.ts`) | `tests/bootstrap.test.ts` for style |
| A new Vue composition | `src/web/entries/<name>/` (`main.ts` exporting `mount`, `contract.toml` declaring `role`/`variant`, optional `main.html`) | `ARCHITECTURE.md` → "How to add things" — `vite.config.ts` is directory-driven; add a `VUE_ROUTES` override only if the derived `{role}-{variant}` name is not enough |
| A new design doc | `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` | existing specs |
| A new implementation plan | `docs/superpowers/plans/YYYY-MM-DD-<topic>.md` | existing plans — **not** `docs/plans/`, see the duplicate-home warning above |
| A new evidence/verification | `routes/<route>/evidence/YYYY-MM-DD-<topic>.md` | existing evidence |
| A new cross-route verification record | `verifications/YYYY-MM-DD-<topic>-verification.md` | `verifications/harness-template-refactor-verification-lite.md` |

⚠ `verifications/` (3 files, 1 tracked) and `routes/<r>/evidence/` overlap: the former holds
harness-meta verifications, the latter route evidence. That split is implied by content, not
written down anywhere until now, and it is not machine-checked.

## Forbidden homes

- **`/scripts/<name>.md`** — scripts are `.ts`, runnable. Docs go in `core/`, `docs/`, or `routes/<r>/`.
- **`/tests/<anything-not-test>.ts`** — `tests/` is for assertion-bearing test files only. Validators / builders / indexers live in `scripts/`.
- **`/skills/<name>/`** without `SKILL.md` + `_meta.json` — `scripts/skills-audit.ts` will flag.
- **Bootstrap outputs at repo root** — root `MEMORY.md` / `AGENTS.md` / etc. are gitignored by design. To change their content, edit the source under `routes/` / `platforms/` / `core/` and re-run `npm run bootstrap`.
- **Runtime artifacts under tracked paths** — anything under `.harness-*-runtime/` or `.ai-runtime-artifacts/` must be in `.gitignore` (it is). `scripts/validate-schemas.ts` will reject tracked files in those dirs.
- **A Vite/npm project under `skills/<name>/`** — `scripts/install-skills.ts:67` junctions the *whole* skill dir into `~/.qoder/skills/`, `~/.codex/skills/` and `~/.claude/skills/`, so `dist/`, `node_modules` and `src/` would be published to every session on the machine. Vue source stays in `src/web/`; skills keep only the scripts that consume `dist/`.
