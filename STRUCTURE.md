# Structure

> What lives where in `harness-factory`. Read this before adding a new file — it
> exists so each directory has exactly one job, and so new files have an obvious
> home.

## Top-level

| Path | Purpose | Mutable? |
|---|---|---|
| `ENTRY.md` | Single source of truth for behavior rules (all 5 platforms). | edit cautiously |
| `CLAUDE.md` / `AGENTS.md` / `GEMINI.md` | Per-platform native entries; **generated by `npm run bootstrap`** (gitignored). | regenerated |
| `LICENSE` | Project license. | frozen |
| `README.md` | Onboarding: what + quick-start. | edit |
| `ARCHITECTURE.md` | Why-the-shape: 5 layers, what was cut, bootstrap contract. | edit |
| `STRUCTURE.md` | This file: where each kind of file lives. | edit |
| `MEMORY.md` | Code-route MEMORY for the **downstream** project (gitignored, bootstrap-generated). | regenerated |
| `package.json` | npm scripts + TS deps. | edit |
| `tsconfig.json` | TS 7 native config. | frozen unless compiler bumps |
| `.mcp.json` | Project-scoped MCP server wiring (committed). | edit |
| `.gitignore` | What stays out of git. | edit |

## Source dirs (canonical, edit these)

```
core/                  8 governance docs (NEVER, ENTRY, principles, ...). Mandatory load.
capabilities/rules/    Per-language rules. 3 verticals: java, typescript, common.
                       4 file types each: hooks.md, patterns.md, security.md, testing.md.
platforms/<p>/rules/   Per-platform deltas. 5 platforms: claude, codex, trae, workbuddy, qoder.
                       codex + qoder share native entry AGENTS.md.
routes/<r>/            Per-domain state. 3 routes: code, novel, news.
                       MEMORY.md is the per-route template.
                       news/ has extra sub-dirs (evidence/, scripts/) because it is the
                       only route that has shipped production code.
skills/                Active skills (49) + skills/archive/ (51). Restorable on demand.
schemas/               JSON schemas: platform / route / skill. Validated by scripts/validate-schemas.ts.
mcp-config/            Canonical MCP server snippets (1 server: codebase-memory).
references/            tooling.md + traps.md — external tool setup notes.
docs/superpowers/      Design specs and implementation plans (historical record).
```

## Code dirs (TS)

```
scripts/               Harness-factory's own meta scripts (run via npm run *).
                       bootstrap, doctor, install-into-project, install-skills,
                       stats, check-bootstrap, skills-audit,
                       build-index, validate-schemas. (10 scripts.)

tests/                 Real tests only. (2 files: bootstrap.test.ts, install-template.test.ts.)
                       The old tests/validate-schemas.ts and tests/build-index.ts moved to
                       scripts/ — they are scripts, not tests.
```

## Bootstrap outputs (gitignored, regenerated)

```
.claude/   .codex/   .trae/   .codebuddy/   .qoder/   # per-platform dirs
AGENTS.md  CLAUDE.md  GEMINI.md  MEMORY.md             # native entries
.harness-novel-runtime/  .harness-news-runtime/  .ai-runtime-artifacts/   # runtime dirs
```

`scripts/check-bootstrap.ts` reports drift between these and their sources.

## Domain runtime (per-route, gitignored)

| Route | Runtime dir | Owns |
|---|---|---|
| `code` | `.ai-runtime-artifacts/` | agent traces, scratch |
| `novel` | `.harness-novel-runtime/` | novel drafts, chapter output |
| `news` | `.harness-news-runtime/` | rendered videos, ledger, articles |

`scripts/stats.ts` reports their sizes (flag >1 GiB).

## Where to add a new thing

| You want to add… | Put it in… | Read |
|---|---|---|
| A new skill | `skills/<name>/SKILL.md` + `_meta.json` | `skills/add-skill/SKILL.md` |
| A new platform | `platforms/<name>/rules/ENTRY.md` | `skills/add-platform/SKILL.md` |
| A new route | `routes/<name>/MEMORY.md` | `skills/add-route/SKILL.md` |
| A new language rule | `capabilities/rules/<lang>/<topic>.md` | this file |
| A new npm script | `scripts/<name>.ts` + `package.json` entry | existing scripts for style |
| A new test | `tests/<name>.test.ts` | `tests/bootstrap.test.ts` for style |
| A new design doc | `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` | existing specs |
| A new implementation plan | `docs/superpowers/plans/YYYY-MM-DD-<topic>.md` | existing plans |
| A new evidence/verification | `routes/<route>/evidence/YYYY-MM-DD-<topic>.md` | existing evidence |

## Forbidden homes

- **`/scripts/<name>.md`** — scripts are `.ts`, runnable. Docs go in `core/`, `docs/`, or `routes/<r>/`.
- **`/tests/<anything-not-test>.ts`** — `tests/` is for assertion-bearing test files only. Validators / builders / indexers live in `scripts/`.
- **`/skills/<name>/`** without `SKILL.md` + `_meta.json` — `scripts/skills-audit.ts` will flag.
- **Bootstrap outputs at repo root** — root `MEMORY.md` / `AGENTS.md` / etc. are gitignored by design. To change their content, edit the source under `routes/` / `platforms/` / `core/` and re-run `npm run bootstrap`.
- **Runtime artifacts under tracked paths** — anything under `.harness-*-runtime/` or `.ai-runtime-artifacts/` must be in `.gitignore` (it is). `scripts/validate-schemas.ts` will reject tracked files in those dirs.
