# engine/gates.md — 门禁三档（唯一定义）

其余任何文件只准引用本文件，禁止复述档位内容——档位内容出现第二份就是漂移起点。

`<!-- gate:X -->` 与 `<!-- /gate:X -->` 之间的块由 `compiler/render.ts` 整块抽走，填进一页纸的
`{{gate.requirements}}`。因此每块**必须恰好 4 行**（动笔前 / 干活中 / 交付时 / 证据形态），
`lint.ts` 按此断言。块外的解释文字不进一页纸。

## 声明格式

开工第一句 `Harness: S`（或 `M` / `L`）。默认档取自 `routes/<line>.md`；
强制升档条件成立时，先声明升档再干活。

## 三档

**S · 直接做** —— 单点改动、问答、查询、不动叙事文本的整理。

<!-- gate:S -->
动笔前：无。
干活中：直接改。
交付时：口头证据——动了什么 / 跑了什么 / 结果如何。
证据形态：三件套齐了才算交付；缺一项即为未完成。
<!-- /gate:S -->

**M · 一页方案** —— 多文件改动、新功能、重构。

<!-- gate:M -->
动笔前：一段话方案（改哪些文件、怎么验、风险在哪），**等用户确认后**再动。
干活中：按方案改；偏离时先说偏离了什么、为什么。
交付时：证据追加到 `.workspaces/<proj>/MEMORY.md` 的日志段。
证据形态：口头三件套 + 方案逐条对照。
<!-- /gate:M -->

**L · 全阶段流程** —— 跨模块、多 task 派发、对外发布。

<!-- gate:L -->
动笔前：`contracts/spec.md` 落盘 → 停 → 等确认 → `contracts/plan.md` 落盘 → 停 → 等确认。
干活中：严格按 plan 执行；多 task 走 `runbooks/multi-task.md`。
交付时：`contracts/closeout.md` 落盘。**未落盘禁止称「批次完成」。**
证据形态：三件套 + 每条验收项逐条打勾 + 验证命令原始输出。
<!-- /gate:L -->

## 升降档

- 用户显式指定档位 → 以指定为准。
- **agent 禁止悄悄降档。** 要降，必须先说明理由并等用户同意。
- 升档随时可做，无需同意。
- **路线管线不随任何档位升降。** news 的多源核对、novel 的写前文风基线与写后机检，
  S 档也照跑。档位只管「方案与收尾的文书重量」，管不着管线。
  v1 把管线与档位混写在同一份文件里，结果是 AI 降档时把查证一起降掉了。

## 无 S 档的路线

- **novel**：凡产出或改写正文，最低 M。唯一例外是不改叙事文本的操作（改错别字、重命名、跑统计）。
  理由：S 的定义是「动笔前无方案」，而长篇崩坏几乎都始于「没想清楚就落这一章」。

## 证据总则

**没有证据不得声称完成。** 适用于全部三档——档位决定证据的形态，不决定证据的有无。
v1 留过「Tier 0 直接提交、零落盘」的口子，v2 不存在该口子。
