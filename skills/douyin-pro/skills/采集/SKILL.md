# 外部内容采集 · content-collector

## 定位

流水线的**可选前置环节**（Path B 端到端直出的第 0 步，也可独立使用）。
当你「没想好拍什么」或「想蹭热点」时，先用采集把全网素材收拢成一份可直接消费的
「采集报告」，再交给中游（抖音脚本优化器）筛选题、写脚本。

> 本模块不负责「写什么」，只负责「从外面捞什么原料」。
> **质量 > 数量**：宁可 5 篇精品，不要 50 篇低质。

## 两种采集模式（按环境自动选）

| 模式 | 依赖 | 适用 | 平台覆盖 |
|------|------|------|---------|
| **零配置模式（默认推荐）** | WorkBuddy 原生 `WebSearch` + `WebFetch` | 所有用户、随时可用、零安装 | 搜索引擎能索引到的任意公开网页（公众号/X/YouTube/B站/GitHub 等经搜索可达） |
| **深度模式（进阶）** | `pip install feedgrab` + multi-search-engine Skill | 已装环境的进阶用户、批量/结构化深挖 | feedgrab 原生 10+ 平台深度抓取 + 16 引擎广度搜索 |

> 零配置模式由「主理人（司远）在本会话内直接调用 WebSearch/WebFetch」完成，无需用户装任何东西，
> 符合 Path B「免费优先、开箱即用」的初衷。
> 深度模式仅在用户明确要求「更深的抓取」或「批量竞品监控」时启用，且需用户自行 `pip install feedgrab`。

---

## 零配置模式操作（WorkBuddy 原生 · 默认）

主理人在会话内这样跑，无需任何外部依赖：

1. **确定主题与范围**
   - 主题关键词（如「大模型进展 2026」）
   - 时间窗（默认近 7 天；热点类可放宽到近 30 天）
   - 平台偏好（公众号 / X / YouTube / B站 / GitHub / 新闻站，可多选）

2. **调用 WebSearch 广撒网**
   - 中文：`[关键词] 2026 最新`；必要时 `site:mp.weixin.qq.com [关键词]`
   - 英文：`[keyword] 2026 latest` + `qdr:w`（近一周）
   - 多引擎 / 多语言各跑 1–2 轮，覆盖不同视角

3. **对高价值结果用 WebFetch 深读**
   - 拿到搜索结果里看起来最相关的 5–10 个 URL
   - 逐条 `WebFetch` 提取：核心摘要、关键要点、金句、适合做视频的切入角度

4. **按下方「输出模板」整理成采集报告**

> ⚠️ WebFetch 对部分平台（微信需登录、YouTube 动态页等）可能受限；
> 此时退回「摘要 + 来源 URL + 金句摘录（仅引用页面可见原文）」，**禁止编造页面没有的内容**。

## 深度模式操作（feedgrab + multi-search-engine）

> 仅在用户已安装环境时使用。安装与运行由用户自行执行，本 skill 只提供命令范式。

```bash
pip install feedgrab
```

```bash
# 微信公众号搜索
feedgrab mpweixin-so "[关键词]" --limit 5
# X/Twitter 搜索
feedgrab x-so "[关键词]" --limit 5
# YouTube 搜索（含字幕提取）
feedgrab ytb-so "[关键词]" --limit 3
# B站搜索
feedgrab bilibili-so "[关键词]" --limit 5
# GitHub 搜索
feedgrab github-so "[关键词]" --limit 5
# 直接抓取指定 URL
feedgrab url "[目标URL]"
# 抓取并下载视频字幕
feedgrab ytb-url "[YouTube URL]" --transcript
```

multi-search-engine 通过 WorkBuddy Skill 工具加载，集成 16 个搜索引擎（7 中文 + 9 英文），
支持时间过滤（`qdr:w` 近一周 / `qdr:m` 近一月）与高级语法（`site:` / `intitle:`）。

## 输出格式（采集报告模板）

每条采集内容必须包含：标题、来源平台、来源 URL、发布时间、核心摘要（50–150 字）、
关键要点（3–5 条）、金句摘录（原文引用）、适合做视频的切入角度、质量评分（1–5 星）。

### 单条内容模板

```markdown
## 📰 [文章/视频标题]

**来源平台**：微信公众号 / X / YouTube / B站 / GitHub / 新闻站
**来源URL**：[可点击跳转的完整链接]
**发布时间**：YYYY-MM-DD
**作者/账号**：[名称]
**热度指标**：阅读/点赞/评论数（如有，没有则省略）

### 核心摘要
（50-150字，用自己的话概括，禁止原文复制粘贴）

### 关键要点
- ✅ 要点1（简洁，20字以内）
- ✅ 要点2
- ✅ 要点3

### 金句摘录
> 原文中最有价值的一句话（必须标注来源页面）
> —— 来源：[来源URL 或 来源账号]

### 适合做视频的点
（说明这条内容做成视频的最佳切入角度，例如："从用户视角讲它改变了什么" / "对比旧方案突出优势"）

**质量评分**：⭐⭐⭐⭐（推荐做视频 / 一般 / 不推荐）
**评分理由**：一句话说明为什么这个分
```

### 采集报告整体结构

```markdown
# 采集报告：[主题关键词]

**采集时间**：YYYY-MM-DD
**采集模式**：零配置（WebSearch/WebFetch） / 深度（feedgrab）
**采集范围**：近7天 / 近一月
**平台覆盖**：微信公众号、X、YouTube、B站、GitHub
**有效内容数**：N 条

---

[内容1]

---

[内容2]

---

## 采集小结

**推荐做视频的内容**：
1. [标题] — 理由
2. [标题] — 理由

**不推荐的内容**：
- [标题] — 原因（重复/过时/价值低）
```

## 采集原则（铁律）

- **时效性优先**：优先采集近 7 天内容；热点类可放宽到近 30 天。
- **质量 > 数量**：宁可 5 篇精品，不要 50 篇低质。同一事件多篇报道保留最有价值的一篇。
- **金句必标来源**：所有金句摘录必须标注来源页面 URL，禁止编造页面没有的内容。
- **合规底线**：不采集明显违规 / 侵权内容；竞品分析仅用于选题启发，不直接搬运文案。
- **下游可消费**：报告结构必须与上方模板一致，便于中游脚本优化器直接消费。

---

## 与流水线的衔接

- **Path B（端到端直出）**：采集报告 → 中游（抖音脚本优化器，对话直跑模式）→
  下游（video-render-engine，edge-tts + HyperFrames 免费直出）。
- **Path A（高质量生产）**：采集是可选前置；用户也可自带选题，跳过采集直接进大脑层。
- 采集报告中的「推荐做视频的内容」列表，是中游筛选题的直接输入。
