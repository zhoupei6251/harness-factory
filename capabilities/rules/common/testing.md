# 通用测试规则

测试随行为和风险选择，复用项目现有框架、测试数据与命令。

- 新增非平凡逻辑、缺陷修复、信任边界或兼容性变更应有能复现问题或验证行为的检查，覆盖相关正常、边界和失败路径。
- 文案、样式和可直接检查的低风险改动无需为流程补测试；不要写逐行重复实现或仅为覆盖率计数的用例。已有项目覆盖率门禁仍需满足。
- 优先受影响函数、调用链或模块的测试；接口、数据或跨模块变化再补相关集成验证，关键用户流程按需做端到端检查。
- 测试独立、可重复，明确准备、动作和断言；验证具体结果与副作用，避免依赖执行顺序。
- 仅隔离必要的外部服务和不确定因素，避免 mock 掉待验证的核心逻辑。不得为了执行本规则引入新测试框架或服务。
- 一组相关编辑完成后运行必要检查。通过后仅因新修改、失败或未解决问题扩大或重复验证。

交付时说明实际命令、结果和限制。遵守项目禁止自动执行的命令；只列出建议命令时明确尚未运行。
