# core/quality-gates.md — 门禁三档（唯一定义）

> 本文件是档位 S/M/L 的**唯一定义**。
> 其他文件只准引用本文件，不准复述档位内容——出现第二份就是漂移起点。

## 声明格式

开工第一句：

```
Harness: S   # 或 M / L
```

默认档取自 `routes/<line>/workflow.md` 的「默认档」。**强制升档条件**成立时，先声明升档再干活。

## 三档（按响应时间由短到长）

### S · 直接做

单点改动 / 问答 / 查询 / 不动叙事文本的整理。

- **动笔前**：无。
- **干活中**：直接改。
- **交付时**：口头三件套——动了什么 / 跑了什么 / 结果如何。
- **证据形态**：动了什么 + 跑了什么 + 结果，三件套齐了才算交付；缺一项 = 未完成。

### M · 一页方案

多文件改动 / 新功能 / 重构。

- **动笔前**：一段话方案（改哪些文件、怎么验、风险在哪），**等用户确认后**再动。
- **干活中**：按方案改；偏离时先说偏离了什么、为什么。
- **交付时**：证据追加到 `.harness/state/MEMORY.md` 的日志段。
- **证据形态**：口头三件套 + 方案逐条对照。

### L · 全阶段流程

跨模块 / 多 task 派发 / 对外发布。

- **动笔前**：`engine/contracts/spec.md` 落盘 → 停 → 等确认 → `engine/contracts/plan.md` 落盘 → 停 → 等确认。
- **干活中**：严格按 plan 执行；多 task 走 `engine/runbooks/multi-task.md`。
- **交付时**：`engine/contracts/closeout.md` 落盘。**未落盘禁止称「批次完成」**。
- **证据形态**：口头三件套 + 每条验收项逐条打勾 + 验证命令原始输出。

## 升降档

| 触发 | 动作 |
|---|---|
| 用户显式指定档位 | 以指定为准 |
| agent 觉得当前档太低（方案/契约/收尾需要更重） | 升档（无需同意） |
| agent 觉得当前档太高（步骤冗余） | 降档（**必须先说明理由并等用户同意**，禁止悄悄降档） |
| 路线默认档 | 生效于第一次 `Harness: X` 声明 |

## 路线默认档与强制升档

| 路线 | 默认档 | 强制升 L 条件 |
|---|---|---|
| code | M | 跨模块改动；多 task 派发；对外发布 |
| novel | **无 S 档** | 凡产出或改写正文，最低 M；唯一例外：不改动叙事文本的操作（改错别字、重命名、跑统计）按 S |
| news | S | 「要发出去 / 投出去」强制 L |

## 路线管线不随档升降

> v1 教训：把管线和档位混写 → AI 降档时把查证一起降掉。

**news 的多源核对**、**novel 的写前文风基线与写后机检**——S 档也照跑。档位只管「方案与收尾的文书重量」，**管不着管线**。

## 无 S 档的路线

- **novel**：理由——长篇崩坏几乎都始于「没想清楚就落这一章」。S 的定义是「动笔前无方案」，而 novel 不动笔也得有方案。

## 证据总则

**没有证据不得声称完成。** 适用于全部三档。

- 档位决定**证据的形态**（口头 / 落盘 / 收尾合同），不决定**证据的有无**。
- v2 留过「Tier 0 直接提交、零落盘」的口子——v3 不存在该口子。

## 怎样在文档里指代

- 「这事是 S 档」= `Harness: S` 走 `<line>/workflow.md` 的默认管线即可
- 「这事要 M 档」= 一段话方案 + 等确认
- 「这是 L 档批次」= spec + plan + closeout 三份合同落盘
- 「升档」= 在对话里说 `Harness: M` / `Harness: L`，重新触发该档的动笔前流程
